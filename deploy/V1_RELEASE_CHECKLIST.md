## 部署前

1. 备份已有 MySQL、Redis 数据；保留队列和数据卷。已有库只执行 `sql/citygo-upgrade.sql`，不重新导入带 DROP TABLE 的基础 SQL。`import-demo.ps1` 会改写演示商户/笔记，运行前核对目标库。
2. 设置数据库/MQ 密码和管理员 ID；核对域名、HTTPS、上传目录、8080 端口及反向代理。Compose 的数据服务不映射公网端口。
3. 停止旧版应用后用 `docker compose up -d --build` 构建启动；本轮改动涉及发号算法，避免新旧实例混用。单纯 restart 不能更新程序。
4. 执行 `docker compose ps`、`docker compose logs --tail=100 app`，确认服务正常，应用启动无数据库列缺失或 MQ 队列参数冲突。
5. 全新演示库核对 `seckill:stock:10` 为 20、`seckill:voucher:10` 有 beginTime/endTime；Compose 初始化只在券 10 无订单且相关 Redis key 全空时写入。部分 key 或历史订单存在时会跳过，不手工覆盖运行中的库存。活动日期按北京时间解释。

## 上线后实际走一遍

1. 匿名打开首页、分类、商户、笔记；搜索含 `&`、`+` 的关键词；确认无浏览器异常、接口 500 和图片 404。
2. 体验登录、刷新、退出；匿名访问受保护接口返回 401，非管理员新增商户/发券被拒绝。
3. 发布笔记、上传图片、点赞/取消、评论/删除、收藏/取消；另一账号无法修改或删除他人的内容。
4. 普通券下单、我的订单、查询、模拟支付；重复支付不重复扣库存。
5. 秒杀下单后轮询到未支付；重复抢购被拒绝，等待超时取消后资格和库存恢复，另一订单可重抢。
6. 留一笔未支付订单，实际等待 15 分钟，确认延迟取消、SQL/Redis 库存恢复；服务日志和队列状态无持续重试。不要为了缩短等待直接删除现有延迟队列。
7. 重启应用后页面、登录态、订单仍正常；确认上传图片和数据库/Redis/MQ 的持久化。
